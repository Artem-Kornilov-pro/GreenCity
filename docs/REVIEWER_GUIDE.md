**Без установки** решение можно проверить на публичном стенде https://baobab24.ru — та же версия в продакшен-режиме. Тестовые чертежи — из [locations/location_test/](../locations/location_test/).

## 1. Запуск

Нужен Docker Desktop (или Docker Engine с любым Compose v2) и около 8 ГБ свободной памяти. Нужен интернет: при сборке скачиваются образы, пакеты Python и npm и исходники LibreDWG (с GitHub, а если он недоступен — с зеркал GNU; если не скачались нигде, образ всё равно собирается, но без загрузки DWG — DXF работает).

```bash
git clone https://github.com/Artem-Kornilov-pro/GreenCity.git
cd GreenCity
cp .env.example .env          # Windows PowerShell: Copy-Item .env.example .env
docker compose up -d --build
```

Первая сборка занимает 5–10 минут. Готовность — `docker compose ps`: у всех восьми сервисов статус `healthy`.

| Адрес | Что там |
|---|---|
| http://localhost:5173 | сайт; API и Swagger — через него же (http://localhost:5173/docs) |
| http://localhost:3001 | Grafana (admin / admin): метрики и логи |

Бэкенд, базы и мониторинг наружу не открыты, к ним обращается только сайт.

**Если что-то мешает запуску** — всё меняется в `.env`, сам `docker-compose.yml` править не нужно (полный список — `.env.example`, раздел «Запуск в Docker»):

| Что случилось | Что сделать |
|---|---|
| порт 5173 или 3001 занят (`port is already allocated`) | `FRONTEND_PORT=8080`, `GRAFANA_PORT=3002` — сайт будет на http://localhost:8080 |
| `mongo` постоянно перезапускается, в логе `Illegal instruction` (процессор или виртуальная машина без AVX) | `MONGO_IMAGE=mongo:4.4`. Сайт, GreenPlan и экспорт работают и без MongoDB — без неё недоступны только регистрация и проекты |
| сайт открывают по имени сервера, а не по `localhost` | ничего — любые имена разрешены (`ALLOWED_HOSTS`) |
| Docker без root, Podman | `DOCKER_SOCKET=/run/user/1000/docker.sock` — для логов в Grafana; сайт работает и без этого |
| ставили прошлую версию и обновили код | `docker compose up -d --build --renew-anon-volumes` — иначе фронтенд останется со старыми npm-пакетами |

Продакшен-режим (`make docker-prod-up`) и публичный стенд с HTTPS (`make docker-public-up`, [PUBLIC_STAND.md](PUBLIC_STAND.md)) требуют Docker Compose 2.24.4 или новее; основной запуск выше — любой Compose v2.

**Ключ языковой модели.** В `.env` задаются `YANDEX_CLOUD_API_KEY` и `YANDEX_CLOUD_FOLDER` (Yandex AI Studio). Без них работают:

- разбор чертежей;
- GreenPlan;
- записка и объяснения;
- экспорт.

Недоступны только ИИ-ассистент, текст-обоснование и визуализации: вместо них — понятное сообщение. Для визуализаций ключу нужна роль `ai.imageGeneration.user`; можно задать отдельный ключ только для картинок — `YANDEX_ART_API_KEY`, `YANDEX_ART_FOLDER`.

Остановить: `docker compose down`.

## 2. Проверка за 15 минут

Тестовые участки лежат в [locations/location_test/](../locations/location_test/). Рядом с каждым DXF — пример результата (`ПОСЛЕ-*.dxf` и записка `.docx`). Подробное описание участков и ориентиры — в [README участков](../locations/location_test/README.md).

| Участок | Что проверяет | Ориентир после GreenPlan |
|---|---|---|
| `01_school/01_school.dxf` | школа: стадион, площадки, хоздвор, сети через двор | около 77 деревьев, 625 кустов, 12 тыс. м² газона |
| `02_boulevard_street/02_boulevard_street.dxf` | улица с бульваром, палисадники, воздушная ЛЭП | около 85 деревьев, 687 кустов |
| `03_courtyard_renovation/03_courtyard_renovation.dxf` | реконструкция двора: плотные сети, существующие деревья | около 51 дерева, 567 кустов |
| `04_customer_layers/04_customer_layers.dxf` | тот же двор, оформленный «как у заказчика»: свои имена слоёв, коды сетей, внешняя ссылка, блоки, миллиметры | после назначения «Слой 7» — как у 03 |

У новой посадки на всех участках — **0 нарушений**.

**Шаги:**

1. **Загрузка.** http://localhost:5173 → «Попробовать без регистрации» → «Загрузить чертёж» → `01_school.dxf` (или перетащить файл в окно). На сцене:
   - здания в 3D;
   - зоны ограничений: красные — нельзя, жёлтые — нежелательно, зелёные — газон;
   - кольца нормативных отступов вокруг зданий;
   - камера: левая кнопка — вращать, правая кнопка или два пальца — двигать центр, колесо — масштаб ([USER_GUIDE.md](USER_GUIDE.md), раздел 3).

2. **Точки и зоны посадки** (ТЗ: «список точек и зон, где возможна посадка»). Наведите мышь на зону — слева её тип и охранное расстояние.

3. **GreenPlan.** «GreenPlan» → «Запустить». Через несколько секунд на сцене посадка, справа панель:
   - стиль участка и проект-аналог;
   - нарушения норм новой посадкой — 0;
   - ведомость по видам и газон в м²;
   - обоснование (с ключом LLM).

4. **Существующие насаждения.** Повторите на участке, где есть деревья с нарушениями, например `locations/10_stary_gay/10_stary_gay.dxf`, с галочкой «Убрать деревья и кусты с нарушением норм». В замечаниях будет, сколько деревьев и кустов удалено и какие нормы они нарушали.

5. **Документы.**
   - «Пояснительная записка (DOCX)» — решения с происхождением, нормы со статусом, ведомость по форме 9 ГОСТ 21.508;
   - «Объяснения посадок: JSON / CSV / Excel» — у каждой посадки ближайшие ограничения, фактическое расстояние, норма, пункт НПА и статус нормы; в Excel — ещё ведомость и таблица всех проверок отступов (невыполненные подсвечены);
   - «Визуализации (ИИ)» (бонус ТЗ, нужен ключ) — три иллюстрации участка после озеленения: вид с дрона, вид пешехода, крупный план.

6. **Экспорт в DXF.** «Экспорт» → «Экспорт в DXF». Исходный чертёж не меняется, новое — на слоях `NEW_*` (и `USER_*`, если были ручные правки), у каждой сущности XDATA с id посадки. Сразу после выгрузки редактор сам проверяет файл заново и показывает полосу «Проверка выгрузки пройдена: сущностей исходника …, пропало 0, изменено 0; посадок проверено …; нарушений норм нет» с SHA-256 исходника.
   - Та же проверка без сайта (нужен Python с `ezdxf`): `python tools/check_export.py locations/location_test/01_school/01_school.dxf <выгруженный.dxf> <объяснения.json>`. Ожидается «ПРОВЕРКА ПРОЙДЕНА».
   - Проверка в nanoCAD и на Linux — [SOLUTION.md, раздел 6](SOLUTION.md#6-проверка-выходного-dxf).

7. **Корректировки в графическом формате.** Клик по дереву → «Двигать», перетащите его на дорогу — объект подсветится как нарушение. Delete — удалить. «Добавить объект» слева — поставить новый.

8. **Корректировки в текстовом формате** (нужен ключ LLM). «Ассистент» → «посади три липы вдоль дорожки у школы», затем «убери их». Под ответом видно, что сделано; координаты считает планировщик по нормам, модель их не выбирает.

9. **Загрузка комплекта.** «Загрузить папку» — папка проекта с `.dwg`/`.dxf`, или «Загрузить чертёж» — несколько файлов объекта (топосъёмка, сети, граница заказа) или zip-архив: всё сливается в одну сцену, DWG конвертируются на сервере через LibreDWG.

10. **Чертёж с любыми именами слоёв.** Загрузите `04_customer_layers/04_customer_layers.dxf`. Слои названы по-своему («Проезды», «В1», «Т1», «Топоплан|Строения»), деревья — блоками с названием породы, газон — штриховкой, единицы — миллиметры без заголовка; всё это распознаётся само. Полоса под панелью называет единственный нераспознанный слой «Слой 7». «Проверить слои» → «Слой 7» → «Трансформаторная подстанция» → «Разобрать заново»: распознано 25 из 25, сцена как у 03. Подробности — [README участков](../locations/location_test/README.md).

11. **Воздушная ЛЭП.** На `02_boulevard_street` откройте параметры GreenPlan: «Класс напряжения ЛЭП» задаёт отступ деревьев по ПУЭ (до кроны 1 м до 1 кВ, 3 м до 20 кВ, 4–7 м выше). В объяснении посадки у ЛЭП видны класс напряжения и пункт ПУЭ.

12. **Подложка карты.** Чертёж в Московской системе координат, например `locations/04_kharkovskaya_ulitsa/04_kharkovskaya_ulitsa.dxf`: кнопка «Карта» кладёт под сцену OpenStreetMap, участок встаёт на свою улицу (нужен интернет).

13. **Проекты и файлы** (нужен вход). Зарегистрируйтесь, «Сохранить как…», запустите GreenPlan: на панели появится «Файлы проекта сохранены» — в окне «Файлы» записка, объяснения JSON/CSV/Excel, DXF с отчётом проверки и визуализации. «Поделиться» даёт ссылку `/share/<ключ>`: проект открывается без входа, только для просмотра.

## 3. Соответствие требованиям ТЗ

| Требование | Где проверить |
|---|---|
| Данные ГИС: DXF, DWG, SHP, GeoJSON | загрузка DXF, DWG, zip и папки проекта в интерфейсе; конвертеры SHP / GeoJSON → DXF — `converters/` |
| Нормативные отступы от сетей и инфраструктуры (СП 42.13330.2016, 743-ПП, МГСН, ПУЭ) | шаги 2–3, 11; таблица норм — [GREENPLAN_ALGORITHM.md](GREENPLAN_ALGORITHM.md#нормативные-отступы); выписки из актов — `data/norms/` |
| Точки и зоны, где возможна посадка | шаг 2 |
| Оптимальный план посадки деревьев и кустарников, травянистые покрытия | шаг 3; алгоритм — [GREENPLAN_ALGORITHM.md](GREENPLAN_ALGORITHM.md) |
| Корректировки в текстовом и графическом формате | шаги 7–8 |
| Экспорт итогового плана в DXF, исходные слои не изменяются | шаг 6 (с автоматической проверкой выгрузки) |

| Описанный алгоритм принятия решения | [GREENPLAN_ALGORITHM.md](GREENPLAN_ALGORITHM.md) |
| Сценарий выгрузки документации | шаг 5 |
| Документация (п. 5): назначение и границы MVP, схема процесса BPMN, интерпретируемость, методы и библиотеки, проверка DXF, ограничения и известные ошибки | [SOLUTION.md](SOLUTION.md), разделы 1–7; схема — [bpmn/greencity_process.bpmn](bpmn/greencity_process.bpmn); PDF — [pdf/](pdf/) |
| Материалы сдачи (п. 7.2.10): Docker-инструкция, примеры входных и выходных DXF | раздел 1 этого документа и [README](../README.md); примеры — [examples/](../examples/) и `ПОСЛЕ-*.dxf` в `locations/location_test/` |

## 4. Что ещё есть

- **Тесты.** Около 1500 автотестов, включая сквозные сценарии через HTTP на реальных DXF, без обращения к платным API: `make test` (нужен Python 3.12+ и `make venv`). Регрессия на корпусе: `make parser-regression`, `make greenplan-regression`.
- **Защита API.** Лимиты частоты и размера запросов, очередь расчётов. Swagger в продакшене выключен ([TECHNICAL_OVERVIEW.md, раздел 2.1](TECHNICAL_OVERVIEW.md#21-асинхронность-очередь-расчётов-защита-и-сеть)).
- **Нагрузка.** На стенде 4 vCPU / 8 ГБ лёгкий API держит около 380–400 запросов в секунду, 10 инженеров одновременно работают без ошибок ([tools/loadtest/README.md](../tools/loadtest/README.md)).
- **Продакшен-режим:** `make docker-prod-up` — сайт на порту 80 за nginx ([README](../README.md)); публичный стенд с HTTPS — `make docker-public-up` ([PUBLIC_STAND.md](PUBLIC_STAND.md)).
- **Аудит эталонов.** Реальные проекты корпуса проверены теми же нормами: 36 % их посадок стоят ближе нормы, у посадок GreenPlan — 0 ([AUDIT_REFERENCES.md](AUDIT_REFERENCES.md)).
- **Ограничения и известные ошибки** — [SOLUTION.md, раздел 7](SOLUTION.md#7-ограничения-допущения-известные-ошибки).

## 1. Запуск

Нужен Docker Desktop (или Docker Engine с Compose v2) и около 8 ГБ свободной памяти.

```bash
git clone https://github.com/Artem-Kornilov-pro/GreenCity.git
cd GreenCity
cp .env.example .env          # Windows PowerShell: Copy-Item .env.example .env
docker compose up -d --build
```

Первая сборка занимает 5–10 минут. Готовность — `docker compose ps`: у всех восьми сервисов статус `healthy`.

| Адрес | Что там |
|---|---|
| http://localhost:5173 | сайт; API и Swagger — через него же (http://localhost:5173/docs) |
| http://localhost:3001 | Grafana (admin / admin): метрики и логи |

Бэкенд, базы и мониторинг наружу не открыты, к ним обращается только сайт.

**Ключ языковой модели.** В `.env` задаются `YANDEX_CLOUD_API_KEY` и `YANDEX_CLOUD_FOLDER` (Yandex AI Studio). Без них работают:

- разбор чертежей;
- GreenPlan;
- записка и объяснения;
- экспорт.

Недоступны только ИИ-ассистент и текст-обоснование: вместо них — понятное сообщение.

Остановить: `docker compose down`.

## 2. Проверка за 15 минут

Тестовые участки лежат в [locations/location_test/](../locations/location_test/). Рядом с каждым DXF — пример результата (`ПОСЛЕ-*.dxf` и записка `.docx`). Подробное описание участков и ориентиры — в [README участков](../locations/location_test/README.md).

| Участок | Что проверяет | Ориентир после GreenPlan |
|---|---|---|
| `01_school/01_school.dxf` | школа: стадион, площадки, хоздвор, сети через двор | около 77 деревьев, 625 кустов, 12 тыс. м² газона |
| `02_boulevard_street/02_boulevard_street.dxf` | улица с бульваром, палисадники, воздушная ЛЭП | около 85 деревьев, 690 кустов |
| `03_courtyard_renovation/03_courtyard_renovation.dxf` | реконструкция двора: плотные сети, существующие деревья | около 51 дерева, 567 кустов |

У новой посадки на всех участках — **0 нарушений**.

**Шаги:**

1. **Загрузка.** http://localhost:5173 → «Попробовать без регистрации» → «Загрузить DXF» → `01_school.dxf` (или перетащить файл в окно). На сцене:
   - здания в 3D;
   - зоны ограничений: красные — нельзя, жёлтые — нежелательно, зелёные — газон;
   - кольца нормативных отступов вокруг зданий;
   - камера: левая кнопка — вращать, правая кнопка или два пальца — двигать центр, колесо — масштаб ([USER_GUIDE.md](USER_GUIDE.md), раздел 3).

2. **Точки и зоны посадки** (ТЗ: «список точек и зон, где возможна посадка»). Наведите мышь на зону — слева её тип и охранное расстояние.

3. **GreenPlan.** «GreenPlan» → «Запустить». Через несколько секунд на сцене посадка, справа панель:
   - стиль участка и проект-аналог;
   - нарушения норм новой посадкой — 0;
   - ведомость по видам и газон в м²;
   - обоснование (с ключом LLM).

4. **Существующие насаждения.** Повторите на участке, где есть деревья с нарушениями, например `locations/10_stary_gay/10_stary_gay.dxf`, с галочкой «Убрать деревья и кусты с нарушением норм». В замечаниях будет, сколько деревьев и кустов удалено и какие нормы они нарушали.

5. **Документы.**
   - «Пояснительная записка (DOCX)» — решения с происхождением, нормы, ведомость по форме 9 ГОСТ 21.508;
   - «Объяснения посадок: JSON / CSV» — у каждой посадки ближайшие ограничения, фактическое расстояние, норма и пункт НПА.

6. **Экспорт в DXF.** «Экспорт» → «Экспорт в DXF». Исходный чертёж не меняется, новое — на слоях `NEW_*` (и `USER_*`, если были ручные правки), у каждой сущности XDATA с id посадки.
   - Проверка без CAD (нужен Python с `ezdxf`): `python tools/check_export.py locations/location_test/01_school/01_school.dxf <выгруженный.dxf> <объяснения.json>`. Ожидается «ПРОВЕРКА ПРОЙДЕНА».
   - Проверка в nanoCAD и на Linux — [SOLUTION.md, раздел 6](SOLUTION.md#6-проверка-выходного-dxf).

7. **Корректировки в графическом формате.** Клик по дереву → «Двигать», перетащите его на дорогу — объект подсветится как нарушение. Delete — удалить. «Добавить объект» слева — поставить новый.

8. **Корректировки в текстовом формате** (нужен ключ LLM). «Ассистент» → «посади три липы вдоль дорожки у школы», затем «убери их». Под ответом видно, что сделано; координаты считает планировщик по нормам, модель их не выбирает.

9. **Загрузка DWG.** «Загрузить DWG (папка)» — папка проекта с `.dwg`, конвертация на сервере через LibreDWG.

## 3. Соответствие требованиям ТЗ

| Требование | Где проверить |
|---|---|
| Данные ГИС: DXF, DWG, SHP, GeoJSON | загрузка DXF и папки DWG в интерфейсе; конвертеры SHP / GeoJSON → DXF — `converters/` |
| Нормативные отступы от сетей и инфраструктуры (СП 42.13330.2016, 743-ПП, МГСН) | шаги 2–3; таблица норм — [GREENPLAN_ALGORITHM.md](GREENPLAN_ALGORITHM.md#нормативные-отступы); выписки из актов — `data/norms/` |
| Точки и зоны, где возможна посадка | шаг 2 |
| Оптимальный план посадки деревьев и кустарников, травянистые покрытия | шаг 3; алгоритм — [GREENPLAN_ALGORITHM.md](GREENPLAN_ALGORITHM.md) |
| Корректировки в текстовом и графическом формате | шаги 7–8 |
| Экспорт итогового плана в DXF, исходные слои не изменяются | шаг 6 |
| Объяснение каждой посадки со ссылкой на НПА и пункт | шаг 5; механизм — [SOLUTION.md, раздел 4](SOLUTION.md#4-интерпретируемость-объяснение-каждой-посадки) |
| Описанный алгоритм принятия решения | [GREENPLAN_ALGORITHM.md](GREENPLAN_ALGORITHM.md) |
| Сценарий выгрузки документации | шаг 5 |
| Документация (п. 5): назначение и границы MVP, схема процесса BPMN, интерпретируемость, методы и библиотеки, проверка DXF, ограничения и известные ошибки | [SOLUTION.md](SOLUTION.md), разделы 1–7; схема — [bpmn/greencity_process.bpmn](bpmn/greencity_process.bpmn); PDF — [pdf/](pdf/) |
| Материалы сдачи (п. 7.2.10): Docker-инструкция, примеры входных и выходных DXF | раздел 1 этого документа и [README](../README.md); примеры — [examples/](../examples/) и `ПОСЛЕ-*.dxf` в `locations/location_test/` |

## 4. Что ещё есть

- **Тесты.** Около 1080 автотестов, включая сквозные сценарии через HTTP на реальных DXF, без обращения к платным API: `make test` (нужен Python 3.12+ и `make venv`).
- **Защита API.** Лимиты частоты и размера запросов, очередь расчётов. Swagger в продакшене выключен ([TECHNICAL_OVERVIEW.md, раздел 2.1](TECHNICAL_OVERVIEW.md#21-асинхронность-очередь-расчётов-защита-и-сеть)).
- **Продакшен-режим:** `make docker-prod-up` — сайт на порту 80 за nginx ([README](../README.md)).
- **Ограничения и известные ошибки** — [SOLUTION.md, раздел 7](SOLUTION.md#7-ограничения-допущения-известные-ошибки).

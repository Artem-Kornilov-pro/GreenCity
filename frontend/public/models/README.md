# 3D-модели

`.glb`-модели посадок и МАФ. Сейчас подключено 49: 34 дерева и 15 МАФ (шезлонги,
лавки/лавочки, стол, стулья, табурет, стол со скамьями). Модель, которой нет в
`manifest.json` (вид из каталога есть, а `.glb` — нет), рисуется примитивом-заглушкой
по габаритам из `backend/core/plant_catalog.py` — это штатный режим, а не ошибка,
именно так работали кусты и МАФ до этого пака.

## Как подключить ещё один пак

Паки с cgtrader и подобных обычно идут в OBJ/FBX/BLEND. Для веба нужен `.glb`
(один бинарник на модель, с упакованными текстурами) — иначе на сотнях моделей
браузер заметно проседает.

```bash
make models SRC=~/Downloads/lowpoly-tree-collection      # OBJ -> GLB
make models SRC=~/Downloads/pack --category bush         # категория по умолчанию tree
```

Скрипт (`tools/convert_models.mjs`) конвертирует все найденные `.obj`, кладёт
`.glb` сюда и **дополняет** (не перезаписывает) два файла:

- `manifest.json` — список реально доступных моделей, по нему фронтенд решает,
  рисовать модель или заглушку;
- `backend/catalog_generated.json` — записи каталога для этих моделей, чтобы они
  сразу появились в панели «Добавить объект» без правок кода.

Повторный запуск для новой партии моделей не стирает то, что записал предыдущий
запуск (для другой категории или пака) — запись с тем же `id` заменяется свежей,
остальные остаются как были.

Если в паке только FBX/BLEND — сначала экспортируйте в OBJ (в Blender:
File → Export → Wavefront .obj), скрипт FBX/BLEND не читает напрямую. Если
Blender недоступен и рук нет — можно вызвать его headless без обычной
установки: скачать `.dmg` с blender.org, смонтировать (`hdiutil attach`) и
экспортировать через `Blender.app/Contents/MacOS/Blender --background
file.blend --python export_script.py` со скриптом на `bpy.ops.wm.obj_export(...)`.

### Точечные правки object_type/label/цвета (overrides.json)

Все `.obj` одной категории (`--category`) получают одинаковые
`object_type`/`label`/`render.shape`/`render.color` из `CATEGORY_DEFAULTS` в
`tools/convert_models.mjs` — этого достаточно для деревьев, но не для МАФ:
шезлонг, стол и табурет не должны все считаться "bench". Если рядом с `.obj`-ами
лежит `overrides.json`:

```json
{
  "lounger_narrow": { "object_type": "lounger", "label": "Шезлонг" },
  "table":          { "object_type": "table",   "label": "Стол" }
}
```

— поля из него точечно перекрывают дефолты категории для конкретного `id`
(берётся из имени файла, см. `toId` в скрипте). Не указанные в overrides поля
не трогаются. Необязательный файл — без него всё работает как раньше.

### Готовый .glb из Blender

Экспорт `.glb` из Blender обычно кладёт в узел поворот Z-up → Y-up, масштаб
объекта и его положение в сцене Blender, а иногда цепляет ещё и лишние
выделенные объекты. Деревья рисуются через `drei.Merged`, который трансформ
узла игнорирует, так что такая модель в сцене ляжет на бок или встанет в
стороне от своей точки. Перед подключением прогоните её через:

```bash
python tools/normalize_glb.py ~/Downloads/yolka.glb frontend/public/models/yolka.glb --height 7.3
```

Скрипт запекает трансформ в вершины, ставит основание в `(0, 0, 0)`,
центрирует по X/Z, масштабирует до заданной высоты в метрах и выкидывает
мелкий мусор. Дальше добавьте путь в `manifest.json` и укажите его в поле
`"model"` нужных записей `backend/catalog_generated.json`, обновив там же
`dimensions.height`/`radius` (скрипт печатает итоговые габариты).

## Соглашения

- Модель должна стоять основанием в точке `(0, 0, 0)` и смотреть вдоль `+Z` —
  иначе объект будет висеть в воздухе или уходить под землю.
- Размер — в метрах, 1 юнит = 1 метр. Экспорт из 3ds Max нередко в дюймах —
  проверяйте габарит получившегося `.glb` по `dimensions` в
  `backend/catalog_generated.json` на предмет вменяемости (стол ростом
  22 метра — это не метры).
- Имя файла становится `id` записи каталога, поэтому латиница без пробелов.
- Общие текстуры (например одна текстура дерева на весь пак) переиспользуются
  автоматически — `obj2gltf --separateTextures` не дублирует файл, если разные
  `.obj` ссылаются на одно и то же имя текстуры.

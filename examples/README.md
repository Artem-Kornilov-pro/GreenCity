# Примеры результата

Три участка из набора кейса после GreenPlan с параметрами по умолчанию. Входные чертежи лежат в `locations/<участок>/<участок>.dxf`.

| Участок | Стиль, ведущий аналог | Новых деревьев | Новых кустарников | Новый газон | Нарушений у новых посадок |
|---|---|---|---|---|---|
| `07_nizhnie_polya` | пейзажный, 19_2ya_pryadilnaya | 290 | 1253 | 670 м² | 0 |
| `06_kamchatskaya_ulitsa` | регулярный, 06_kamchatskaya_ulitsa | 80 | 660 | 12 748 м² | 0 |
| `12_natashinsky_proezd` | пейзажный, 12_natashinsky_proezd | 115 | 483 | 2085 м² | 0 |

В папке участка:

| Файл | Что в нём |
|---|---|
| `<участок>_greenplan.dxf` | выходной DXF: исходный чертёж без изменений и слои `NEW_TREE`, `NEW_BUSH`, `NEW_LAWN`; у каждой новой сущности XDATA `GREENCITY` с id посадки |
| `<участок>_explanations.json` | объяснение каждой посадки: вид, координаты в чертеже, приём и аналог, основание подбора вида, ближайшие ограничения с нормой и пунктом НПА; отклонённые по норме точки; зоны запрета посадки |
| `<участок>_explanations.csv` | то же таблицей: разделитель «;», UTF-8 с BOM (открывается в Excel) |
| `<участок>_note.docx` | пояснительная записка с ведомостью по форме 9 ГОСТ 21.508 (без приложения с текстом ИИ) |
| `summary.json` | сводка и ведомость по видам |

Пересобрать (LLM не вызывается):

```bash
.venv/bin/python tools/build_examples.py
```

Проверить, что исходник в выходном DXF не тронут и что посадки совпадают с файлом объяснений:

```bash
.venv/bin/python tools/check_export.py locations/07_nizhnie_polya/07_nizhnie_polya.dxf \
    examples/07_nizhnie_polya/07_nizhnie_polya_greenplan.dxf \
    examples/07_nizhnie_polya/07_nizhnie_polya_explanations.json
```

Реальные участки сами входят в корпус аналогов, поэтому ведущим аналогом может оказаться сам участок. Подробнее — [docs/SOLUTION.md](../docs/SOLUTION.md), раздел 8.
